Глоссарий

Глоссарий основных терминов и понятий

В глоссарии представлены основные термины и понятия, используемые при изучении системы «1С:Предприятие» и выполнении лабораторных работ электронного практикума.

Используйте глоссарий для уточнения значения терминов и повторения изученного материала.

Алфавитный указатель: А   В   Г   Д   Ж   З   И   К   М   Н   О   П   Р   С   Т   У   Ф   Ц   Э   Я   R
А

Автоматизация предприятия — процесс применения информационных технологий для выполнения производственных, учетных, управленческих и других бизнес-процессов с минимальным участием человека.

Агрегатные функции — функции языка запросов, предназначенные для выполнения вычислений над группами записей. К основным относятся КОЛИЧЕСТВО(), СУММА(), МИНИМУМ(), МАКСИМУМ() и СРЕДНЕЕ().

Аутентификация — механизм определения пользователя, подключающегося к информационной базе. В учебном варианте может выполняться по имени пользователя и паролю. Аутентификация отвечает на вопрос «кто пользователь?».

Авторизация — определение действий, которые разрешено выполнять уже идентифицированному пользователю. В отличие от аутентификации отвечает на вопрос «что пользователю разрешено?».

В

Встроенный язык «1С:Предприятие» — предметно-ориентированный язык программирования, являющийся частью технологической платформы и предназначенный для описания алгоритмов работы прикладного решения.

Выражение — конструкция встроенного языка, в результате вычисления которой получается некоторое значение. Выражения могут содержать арифметические, логические операции и операции сравнения.

Г

Группировка данных — объединение записей по одинаковому значению выбранного поля для их структурированного представления или получения итоговых показателей. В языке запросов для этого используется конструкция СГРУППИРОВАТЬ ПО.

Д

Движение регистра — запись, формируемая при проведении документа и отражающая изменение учетного показателя. Движение содержит значения измерений, ресурсов и реквизитов регистра.

Дерево конфигурации — иерархическое представление объектов метаданных прикладного решения. Используется разработчиком для создания, редактирования, удаления объектов и настройки их свойств.

Документ — объект конфигурации, предназначенный для регистрации хозяйственных операций и событий предметной области. Документ отражает факт совершения определенного действия в конкретный момент времени.

Документирование прикладного решения — подготовка документации, описывающей назначение и структуру системы, основные объекты, роли пользователей, порядок работы с формами и документами, программные механизмы и результаты тестирования. Документирование облегчает дальнейшее сопровождение системы.

Ж

Журнал документов — объект конфигурации, предназначенный для представления списка документов различных видов и организации их совместного просмотра.

З

Запись документа — сохранение введенной пользователем информации в информационной базе. Запись сама по себе не изменяет учетные показатели.

Запрос — средство получения требуемого набора данных из информационной базы. Запрос позволяет описать, какие данные необходимо получить, после чего платформа организует их получение.

И

Измерение регистра — элемент структуры регистра, определяющий направление аналитического учета, то есть разрез, по которому необходимо разделять данные. Например, для учета остатков измерениями могут быть товар и склад.

Информационная база — компонент системы «1С:Предприятие», в котором хранятся данные прикладного решения. В архитектуре системы информационная база используется совместно с платформой и конфигурацией.

Информационная система (ИС) — совокупность программных, технических, информационных, организационных и человеческих ресурсов, предназначенных для автоматизации процессов хранения, обработки, передачи и использования информации.

Итог отчета — обобщенное значение, рассчитанное для группы записей или для отчета в целом. В качестве итоговых операций могут использоваться сумма, количество, среднее, минимальное и максимальное значения.

К

Клиентский контекст — контекст выполнения программного кода на стороне, непосредственно взаимодействующей с пользователем и обеспечивающей работу пользовательского интерфейса. Для указания клиентского выполнения применяется директива &НаКлиенте.

Коллекция — объект, содержащий совокупность элементов и предоставляющий средства работы с ними. К коллекциям относятся массивы, структуры, соответствия, таблицы значений, табличные части и коллекции элементов формы.

Команда формы — действие, которое пользователь может инициировать из интерфейса. Команда может быть представлена кнопкой или другим элементом командного интерфейса.

Комплексное тестирование — проверка прикладного решения посредством выполнения сквозного пользовательского сценария, включающего последовательную работу нескольких взаимосвязанных объектов и механизмов системы. Позволяет выявить ошибки их совместного функционирования.

Конфигуратор — режим работы системы «1С:Предприятие», предназначенный для разработки и изменения конфигурации. В конфигураторе разработчик создает и настраивает объекты метаданных, формы, программные модули, роли и другие компоненты прикладного решения. Разработка конфигурации выполняется именно в этом режиме.

Конфигурация — прикладное решение, разработанное для автоматизации конкретной предметной области. Она представляет собой совокупность объектов метаданных, программных модулей, форм, отчетов и других компонентов и определяет структуру информационной системы и правила обработки данных.

Конфигурация базы данных — фактическая структура прикладного решения, используемая информационной базой при работе системы. После внесения изменений в конфигурацию разработчик должен выполнить обновление конфигурации базы данных, чтобы изменения стали доступны при запуске прикладного решения.

Корпоративная информационная система (КИС) — информационная система, обеспечивающая автоматизацию деятельности предприятия и объединяющая данные его подразделений в едином информационном пространстве.

Критерии готовности прикладного решения — совокупность требований, выполнение которых позволяет считать разработанную систему готовой к эксплуатации. К ним относятся реализация функциональных требований, отсутствие выявленных ошибок, корректная работа запросов, форм и команд, настройка прав доступа, проведение тестирования, подготовка документации, обновление конфигурации базы данных и создание резервной копии.

М

Массив — коллекция встроенного языка, предназначенная для хранения упорядоченного набора значений. Может использоваться для временного хранения списков объектов, результатов вычислений и других данных.

Метаданные — данные о данных, определяющие структуру, состав и свойства объектов информационной системы. Метаданные описывают хранимые данные, способы их обработки, отображения и взаимосвязи.

Метод объекта — операция, которую способен выполнить объект. В программном коде вызов метода обычно выполняется с использованием точечной нотации: Объект.Метод().

Модуль объекта — программный модуль, предназначенный для размещения кода, связанного с поведением конкретного прикладного объекта. В модуле объекта документа могут располагаться алгоритмы проверки, записи, проведения и отмены проведения.

Модуль формы — программный модуль, предназначенный для реализации поведения пользовательской формы. В нем размещаются обработчики команд, событий формы и ее элементов, а также вспомогательные процедуры и функции интерфейса.

Н

Негативное тестирование — проверка реакции системы на ошибочные или неполные исходные данные. Система должна корректно сообщить пользователю о проблеме и не допустить неправильного выполнения операции.

О

Обновление конфигурации базы данных — процедура применения изменений, внесенных разработчиком в конфигурацию, к структуре используемой информационной базы. Общая последовательность включает изменение конфигурации, проверку, сохранение, обновление конфигурации базы данных и контрольный запуск системы.

Обработчик события — процедура, связанная с определенным событием и вызываемая платформой при его наступлении.

Общий модуль — программный модуль, предназначенный прежде всего для размещения процедур и функций, которые могут использоваться из разных частей конфигурации.

Объект встроенного языка — программная сущность, объединяющая данные и средства работы с ними. Состояние объекта характеризуется свойствами, а выполняемые операции — методами.

Объект конфигурации — элемент метаданных, предназначенный для описания определенного аспекта информационной системы. Объекты обладают свойствами, структурой, поведением и механизмами взаимодействия.

Отбор — условие, ограничивающее состав данных, включаемых в отчет. Позволяет формировать отчет только по данным, соответствующим заданным критериям.

Отладка — процесс поиска причины обнаруженной программной ошибки. Отладчик позволяет устанавливать точки останова, выполнять код пошагово, анализировать переменные и последовательность вызовов.

Отчет — объект конфигурации, предназначенный для получения, обработки, группировки и представления данных информационной системы в форме, удобной для анализа.

П

Параметр отчета — значение, задаваемое перед формированием отчета и используемое при получении данных. Например, дата, период, товар или склад.

Параметр запроса — значение, передаваемое запросу во время выполнения программы. В тексте запроса обозначается символом &, а конкретное значение устанавливается программно.

Переменная — именованная область, значение которой может использоваться и изменяться в процессе выполнения программы.

Платформа «1С:Предприятие» — программная среда, обеспечивающая разработку, выполнение и сопровождение прикладных информационных систем. Платформа предоставляет готовые механизмы хранения данных, интерфейса, запросов, отчетов, разграничения доступа и программирования бизнес-логики.

Подсистема — объект конфигурации, предназначенный для логической организации прикладного решения и группировки объектов по функциональному назначению.

Позитивное тестирование — проверка выполнения предусмотренной операции при корректных исходных данных. Например, пользователь правильно заполняет необходимые данные документа и успешно выполняет его проведение.

Пользователь — конкретная учетная запись, под которой человек работает с информационной базой.

Пользовательский интерфейс — совокупность программных и визуальных средств, посредством которых пользователь взаимодействует с информационной системой.

Пользовательский реквизит — дополнительное свойство объекта конфигурации, предназначенное для хранения значения, необходимого для конкретной предметной области.

Право доступа — разрешение на выполнение определенного действия с объектом прикладного решения. Права могут предоставляться на чтение, добавление, изменение, удаление, проведение документов, просмотр отчетов, работу с регистрами и другие действия.

Принцип минимально необходимых прав — подход, согласно которому пользователь получает только те права, которые необходимы ему для выполнения служебных обязанностей.

Программный модуль — часть прикладного решения, содержащая программный код встроенного языка и связанная с определенным объектом, формой либо областью функциональности конфигурации.

Проведение документа — механизм обработки данных документа, в результате которого хозяйственная операция отражается в системе учета посредством формирования записей в регистрах и изменения учетных показателей.

Процедура — именованный фрагмент программного кода, предназначенный для выполнения определенной последовательности действий.

Псевдоним в запросе — более удобное имя, присваиваемое источнику данных или полю с помощью конструкции КАК. Особенно полезен при работе со сложными запросами и несколькими источниками.

Р

Разграничение прав доступа — механизм ограничения доступа пользователей к данным и операциям в зависимости от выполняемых ими обязанностей.

Регистр — объект конфигурации, предназначенный для хранения и обработки структурированных учетных данных, необходимых для ведения учета и последующего анализа.

Регистр накопления — объект конфигурации, предназначенный для хранения и накопления количественных или стоимостных показателей, изменяющихся в результате хозяйственных операций.

Регистр оборотов — вид регистра накопления, предназначенный для учета изменений показателей за определенный период без расчета текущего остатка.

Регистр остатков — вид регистра накопления, предназначенный для получения текущего состояния учитываемого показателя на определенный момент времени.

Регистр сведений — объект конфигурации, предназначенный для хранения характеристик объектов предметной области, которые не требуют накопления количественных или стоимостных показателей.

Режим «1С:Предприятие» — режим работы системы, предназначенный для непосредственной эксплуатации прикладного решения пользователями: ввода и обработки данных, работы со справочниками и документами, выполнения команд, формирования отчетов и других прикладных операций.

Резервная копия информационной базы — копия информационной базы, создаваемая для возможности восстановления рабочего состояния системы при ошибках обновления, повреждении базы, неправильном изменении объектов, удалении данных или других непредвиденных ситуациях.

Реквизит — свойство объекта конфигурации, предназначенное для хранения определенного значения.

Реквизит формы — элемент структуры данных формы, предназначенный для хранения значения, используемого в процессе работы формы. Реквизит формы может быть связан с прикладным объектом либо существовать только внутри формы.

Ресурс регистра — показатель регистра, который накапливается или изменяется. Например, количество, стоимость или сумма.

Роль — совокупность разрешений, определяющих, какие действия пользователь может выполнять в системе. Одному пользователю может быть назначено несколько ролей.

С

Серверный контекст — контекст выполнения программного кода на серверной стороне, предназначенный для соответствующих операций обработки данных и прикладной логики. Для указания серверного выполнения применяется директива &НаСервере.

Синтаксис — совокупность правил записи конструкций языка программирования. Код встроенного языка состоит из операторов, выражений, идентификаторов, ключевых слов, литералов и комментариев.

Синтаксическая ошибка — ошибка, связанная с нарушением правил записи конструкций встроенного языка, например с пропуском ключевого слова или неправильным завершением конструкции.

Система компоновки данных (СКД) — механизм платформы, предназначенный для декларативного описания получения, обработки, группировки и представления данных.

Сквозной пользовательский сценарий — последовательность взаимосвязанных действий пользователя, охватывающая несколько функций и объектов прикладного решения. Например: создание справочных данных → создание документа → заполнение данных → проведение → получение результата → просмотр отчета.

Событие — определенный момент жизненного цикла объекта или пользовательского интерфейса, при наступлении которого платформа может выполнить связанный с ним программный обработчик.

Сортировка — установление порядка расположения записей по определенному признаку, например по алфавиту, дате, количеству или сумме. В запросах применяется конструкция УПОРЯДОЧИТЬ ПО.

Справочник — объект конфигурации, предназначенный для хранения и систематизации условно-постоянной информации, например сведений о товарах, клиентах, поставщиках или складах.

Свойство объекта — характеристика объекта или связанное с ним значение. Для обращения к свойству применяется точечная нотация, например Объект.Склад.

Т

Таблица значений — объект встроенного языка, предназначенный для работы с временными данными табличной структуры и состоящий из строк, колонок и находящихся на их пересечении значений.

Табличная часть — структурированный набор однотипных строк, входящий в состав прикладного объекта и предназначенный для хранения переменного количества повторяющихся данных.

Тестирование — комплексная проверка прикладного решения, позволяющая выявлять синтаксические, логические и исполнительные ошибки, проблемы запросов, интерфейса, прав доступа и взаимодействия объектов.

Тестирование прав доступа — проверка системы от имени пользователей с различными ролями с целью убедиться как в наличии разрешенных операций, так и в отсутствии действий, которые конкретный пользователь выполнять не должен.

У

Управляемая форма — описание пользовательского интерфейса, структура и поведение которого обрабатываются механизмами платформы. Управляемая форма выступает посредником между пользователем и прикладными объектами системы.

Ф

Форма — объект пользовательского интерфейса, предназначенный для отображения данных и организации взаимодействия пользователя с прикладным решением.

Форма выбора — управляемая форма, предназначенная для выбора необходимого объекта из некоторого множества.

Форма объекта — управляемая форма, предназначенная для просмотра и редактирования одного прикладного объекта.

Форма списка — управляемая форма, предназначенная для отображения множества объектов одного типа.

Функциональное тестирование — проверка соответствия фактического поведения системы требованиям, предъявляемым к ее функциям. В рамках курса включает проверку справочников, документов, форм, запросов и других механизмов прикладного решения.

Функция — именованный фрагмент программного кода, выполняющий определенные действия и возвращающий значение вызывающему коду.

Ц

Цикл — конструкция встроенного языка, предназначенная для многократного выполнения фрагмента программного кода. Может применяться, в частности, для последовательного перебора элементов коллекции.

Цифровая экономика — система экономических отношений, основанная на широком использовании цифровых технологий, данных и информационных ресурсов для повышения эффективности производства, управления и предоставления услуг.

Э

Элемент формы — визуальная составляющая пользовательского интерфейса. К элементам формы относятся поля, таблицы, группы, кнопки, надписи, флажки и другие средства представления данных и взаимодействия с пользователем.

Я

Язык запросов 1С — специализированный язык, предназначенный для получения и обработки данных информационной базы в соответствии с заданными условиями.

R

RLS (Record Level Security) — механизм ограничения доступа на уровне отдельных записей информационной базы. Позволяет пользователям с одинаковыми правами на объект получать разные наборы данных в соответствии с установленными ограничениями.
