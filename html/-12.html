Лабораторная работа № 12

Программирование управляемых форм

Цель работы

получить практические навыки программирования управляемых форм в системе «1С:Предприятие», создания команд и их обработчиков, программного обращения к реквизитам и элементам формы, а также управления свойствами элементов пользовательского интерфейса.

В результате выполнения лабораторной работы студент должен уметь:

  • создавать дополнительные реквизиты управляемой формы;
  • создавать собственные команды формы;
  • создавать обработчики команд;
  • размещать команды в пользовательском интерфейсе;
  • программно обращаться к реквизитам формы;
  • обращаться к элементам формы через коллекцию «Элементы»;
  • программно изменять видимость и доступность элементов;
  • создавать динамическое поведение пользовательского интерфейса;
  • различать данные формы и элементы пользовательского интерфейса;
  • определять задачи, которые целесообразно реализовывать в модуле формы.

Порядок выполнения работы

Для выполнения лабораторной работы будем использовать существующую форму документа «Поступление товаров», созданную и настроенную в предыдущих лабораторных работах.

Новый объект конфигурации создавать не требуется.

Задание 1. Подготовка формы документа к программированию

Запустите информационную базу в режиме «Конфигуратор».

В дереве конфигурации последовательно откройте:

Документы → ПоступлениеТоваров → Формы → ФормаДокумента.

Перейдите на вкладку «Элементы» и рассмотрите существующую структуру формы.

Убедитесь, что форма содержит основные реквизиты документа, в том числе:

  • склад;
  • поставщика;
  • табличную часть товаров;
  • другие элементы, созданные ранее.
  • Перейдите на вкладку «Модуль».

После выполнения лабораторной работы № 11 модуль формы может содержать созданные ранее учебные обработчики, например «ПриОткрытии» и «ПоказатьИнформацию».

Если в них остались диагностические команды Сообщить(), использовавшиеся только для исследования событий, их целесообразно удалить, чтобы они не мешали выполнению новой работы.

Контрольный результат

Необходимо увидеть взаимосвязь трех компонентов:

Реквизиты формы → Элементы формы → Модуль формы.

Задание 2. Создание дополнительного реквизита формы

Создадим реквизит, который будет использоваться только пользовательским интерфейсом и не станет реквизитом самого документа.

В редакторе формы перейдите на вкладку «Реквизиты».

Добавьте новый реквизит. Укажите:

Имя: «РезультатПроверки»

Тип: Строка

Данный реквизит будет содержать результат программной проверки данных документа.

Обратите внимание: реквизит «РезультатПроверки» относится к форме, а не к объекту документа.

Следовательно, его значение используется в интерфейсе и не становится новым реквизитом документа «ПоступлениеТоваров».

Контрольный результат.

В списке реквизитов формы должен появиться реквизит «РезультатПроверки — Строка».

Задание 3. Размещение реквизита на форме

Теперь необходимо предоставить пользователю возможность видеть значение созданного реквизита.

Шаг 1. На вкладке «Реквизиты» найдите «РезультатПроверки».

Шаг 2. Перетащите его в дерево элементов формы.

Разместите поле в удобной области формы, например после основных реквизитов документа и перед табличной частью «Товары».

Шаг 3. Для созданного элемента задайте заголовок «Результат проверки».

Таким образом:

  • РезультатПроверки — реквизит формы, содержащий данные;
  • поле «Результат проверки» — элемент формы, отображающий эти данные пользователю (Рисунок 12.2).

Это различие необходимо учитывать при дальнейшем программировании.

Задание 4. Создание команды формы

Создадим собственную команду, с помощью которой пользователь сможет выполнить проверку данных документа.

Шаг 1. Перейдите на вкладку «Команды» редактора формы.

Шаг 2. На вкладке «Команды формы» нажать кнопку «Добавить».

Шаг 3. Задайте свойства:

Имя: «ПроверитьДанные».

Заголовок: «Проверить данные».

Шаг 4. Для команды необходимо создать обработчик действия:

  • В свойствах команды найдите строку «Действие». Нажмите кнопку выбора.
  • Откроется окно «Создание обработчика команды». Для нашего задания выбирайте «Создать на клиенте».

Почему именно этот вариант? Команда пока будет работать непосредственно с интерфейсом формы - изменять значение реквизита «РезультатПроверки». Для этого серверная процедура нам не требуется.

  • После нажатия ОК платформа должна открыть вкладку «Модуль» и автоматически создать обработчик примерно следующего вида:

&НаКлиенте

Процедура ПроверитьДанные(Команда)

// Вставить содержимое обработчика.

КонецПроцедуры

На этом этапе пока не вводите программный код проверки. Сначала убедитесь, что обработчик действительно появился. Обратите внимание на структуру:

&НаКлиенте — указывает клиентский контекст выполнения;

ПроверитьДанные — имя процедуры;

Команда — параметр обработчика;

КонецПроцедуры — завершение процедуры.

Шаг 5. Вернитесь к редактору формы.

  • Перейдите с вкладки «Модуль» обратно на вкладку «Форма».
  • Откройте вкладку «Команды».

У команды ПроверитьДанные свойство «Действие» теперь должно быть заполнено — это означает, что команда связана с созданным обработчиком.

Задание 5. Размещение команды «Проверить данные» на форме

На предыдущем этапе была создана команда «ПроверитьДанные» и связанный с ней обработчик. Однако наличие команды в списке команд формы еще не означает, что пользователь сможет выполнить ее непосредственно из интерфейса. Для этого команду необходимо разместить на форме.

Шаг 1. Перейдите к структуре элементов формы:

  • В редакторе формы документа «Поступление товаров» перейдите на вкладку «Элементы».

В левой части окна отображается дерево элементов формы. В верхней части дерева имеется элемент «Командная панель».

На этой панели уже располагаются стандартные команды документа, которые в режиме «1С:Предприятие» отображаются, например, как кнопки: «Провести и закрыть», «Записать», «Провести», «Еще».

Именно в эту область целесообразно добавить созданную команду «Проверить данные».

Шаг 2. Найдите созданную команду:

В правой части редактора перейдите на вкладку «Команды», а затем выберите вкладку «Команды формы».

В списке должна находиться созданная ранее команда «ПроверитьДанные».

Перед продолжением еще раз убедитесь, что для нее задан заголовок «Проверить данные», а свойство «Действие» связано с обработчиком ПроверитьДанные.

Шаг 3. Добавьте команду в командную панель:

В списке «Команды формы» выделите команду «ПроверитьДанные».

Перетащите ее мышью из правой области редактора в левое дерево «Элементы» на элемент «Командная панель».

При успешном выполнении операции в составе командной панели должен появиться новый элемент, связанный с командой «ПроверитьДанные».

То есть структура формы будет иметь примерно следующий вид:

Форма

├─ Командная панель

│ └─ ПроверитьДанные

├─ ОсновныеДанные

│ ├─ Номер

│ ├─ Дата

│ ├─ Поставщик

│ ├─ Склад

│ ├─ Комментарий

│ └─ РезультатПроверки

└─ СоставДокумента

└─ Товары

Если перетаскивание непосредственно на командную панель не выполняется, сначала выделите «Командная панель», а затем попробуйте перетащить команду повторно. Важно, чтобы создаваемый элемент относился именно к командной панели формы.

Шаг 4. Проверьте предварительное представление формы:

После добавления команды обратите внимание на нижнюю область редактора, где отображается предварительный вид формы.

На командной панели должна появиться новая кнопка с заголовком «Проверить данные».

При этом следует различать три связанных компонента:

Компонент Назначение
ПроверитьДанные в списке команд Команда формы
Кнопка «Проверить данные» Элемент пользовательского интерфейса
ПроверитьДанные(Команда) Программный обработчик команды

Таким образом, кнопка не содержит алгоритм проверки сама по себе. Она предоставляет пользователю возможность выполнить связанную с ней команду, а программный алгоритм располагается в обработчике команды в модуле формы.

Шаг 5. Проверьте связь кнопки с командой:

Выделите созданный элемент «Проверить данные» в дереве элементов формы.

В панели «Свойства» проверьте, что элемент связан с командой ПроверитьДанные. Названия конкретных свойств могут несколько различаться в зависимости от версии платформы, поэтому главное здесь — убедиться, что кнопка создана именно путем размещения ранее созданной команды, а не как отдельная несвязанная кнопка.

На этом этапе не нужно создавать новый обработчик. Он уже был создан в задании 4.

Шаг 6. Сохраните изменения:

После размещения команды сохраните внесенные изменения Файл → Сохранить или используйте соответствующую кнопку панели инструментов.

На данном этапе запускать режим «1С:Предприятие» еще не обязательно, поскольку тело обработчика пока не содержит нашего основного алгоритма проверки. Его мы добавим в следующем задании.

Контрольный результат

В результате выполнения задания созданная команда ПроверитьДанные размещена на командной панели управляемой формы документа (Рисунок 12.4). В пользовательском интерфейсе команда представлена кнопкой «Проверить данные», выполнение которой связано с ранее созданным обработчиком команды.

Задание 6. Программное изменение значения реквизита формы

Шаг 1. Откройте модуль формы. Найдите созданный обработчик команды «ПроверитьДанные».

Шаг 2. Добавьте в него программный код:

&НаКлиенте

Процедура ПроверитьДанные(Команда)

РезультатПроверки = "Проверка выполнена";

КонецПроцедуры

Шаг 3. Сохраните конфигурацию и обновите конфигурацию базы данных.

Шаг 4. Запустите систему в режиме «1С:Предприятие». Откройте документ «Поступление товаров» и нажмите кнопку «Проверить данные».

В поле «Результат проверки» должна появиться строка «Проверка выполнена».

Что произошло?

Пользователь выполнил команду, платформа вызвала обработчик команды, а программный код изменил значение реквизита формы:

РезультатПроверки = "Проверка выполнена";

Связанный с реквизитом элемент формы автоматически отобразил новое значение.

Схема выполнения:

Кнопка → Команда → Обработчик → Изменение реквизита →Оотображение результата на форме.

Задание 7. Добавление проверки данных документа

В предыдущем задании обработчик команды «ПроверитьДанные» всегда присваивал реквизиту формы одно и то же значение:

РезультатПроверки = "Проверка выполнена";

Теперь необходимо изменить алгоритм так, чтобы результат зависел от того, заполнен ли реквизит документа «Склад».

Шаг 1. Откройте модуль формы:

  • В Конфигураторе откройте Документы → ПоступлениеТоваров → Формы → ФормаДокумента.
  • Перейдите на вкладку «Модуль». Найдите созданный ранее обработчик команды:

&НаКлиенте

Процедура ПроверитьДанные(Команда)

РезультатПроверки = "Проверка выполнена";

КонецПроцедуры

Новый обработчик создавать не нужно.

Шаг 2. Замените содержимое обработчика:

Удалите только строку «РезультатПроверки = "Проверка выполнена"» и вместо нее введите:

Если Не ЗначениеЗаполнено(Объект.Склад) Тогда

РезультатПроверки = "Необходимо указать склад";

Иначе

РезультатПроверки = "Данные заполнены корректно";

КонецЕсли;

Шаг 3. Разберите обращение «Объект.Склад»:

В форме документа основной реквизит «Объект» содержит данные редактируемого документа.

Поэтому запись «Объект.Склад» означает обращение к реквизиту «Склад» документа, который в данный момент открыт в форме.

Здесь важно различать:

«Объект.Склад» - данные самого документа

«РезультатПроверки - дополнительный реквизит формы, созданный нами специально для отображения результата проверки.

То есть программа берет данные документа и на их основании изменяет данные формы.

Шаг 4. Разберите условие проверки:

Строка «Если Не ЗначениеЗаполнено(Объект.Склад) Тогда» проверяет, заполнен ли реквизит Склад.

Функция «ЗначениеЗаполнено(...)» возвращает логический результат проверки заполненности значения.

Ключевое слово «Не» меняет результат на противоположный.

Поэтому условие читается следующим образом:

Если склад не заполнен, тогда...

В этом случае выполняется: «РезультатПроверки = "Необходимо указать склад";».

Если склад заполнен, выполняется ветвь «Иначе»:

«РезультатПроверки = "Данные заполнены корректно";»

Шаг 5. Сохраните изменения:

  • Сохраните модуль формы и конфигурацию.
  • Затем обновите конфигурацию базы данных.
  • Запустите систему в режиме «1С:Предприятие».

Шаг 6. Проверьте первый вариант, т.е. склад не указан:

  • Создайте новый документ «Поступление товаров» либо используйте тестовый документ.
  • Очистите поле «Склад», чтобы оно осталось незаполненным.
  • Нажмите кнопку «Проверить данные».
  • В поле «Результат проверки» должно появиться «Необходимо указать склад» (Рисунок 12.6).

При этом документ мы пока не проводим. Задача данного этапа - исследовать именно работу интерфейсной команды проверки.

Шаг 7. Проверьте второй вариант, т.е. когда склад заполнен:

  • Теперь выберите склад, например существующий «РозничныйСклад».

Повторно нажмите «Проверить данные».

Поле должно изменить значение на «Данные заполнены корректно» (Рисунок 12.7).

Это показывает, что одна и та же команда выполняет разные действия в зависимости от текущих данных документа.

Контрольный результат.

В результате выполнения задания реализован обработчик команды, анализирующий значение реквизита «Склад» редактируемого документа. В зависимости от результата проверки программно изменяется реквизит формы «РезультатПроверки», значение которого отображается пользователю в соответствующем поле.

Задание 8. Программное управление видимостью элемента формы

Теперь необходимо дополнительно управлять тем, отображается ли связанное с этим реквизитом поле на форме.

Шаг 1. Проверьте имя элемента формы:

Шаг 5. Сделайте начальное состояние поля невидимым:

Чтобы действие строки «Видимость = Истина» стало наглядным, необходимо сначала скрыть поле при открытии формы.

Самый простой вариант для учебного задания — установить это свойство в Конфигураторе.

  • Вернитесь на вкладку «Форма» → «Элементы».
  • Выделите элемент «РезультатПроверки».
  • В его свойствах найдите «Видимость» и снимите флажок.

Теперь при первоначальном открытии документа поле «Результат проверки» не должно отображаться.

Реквизит «РезультатПроверки» при этом не удаляется. Мы скрываем только визуальный элемент, связанный с ним.

Шаг 6. Сохраните и обновите конфигурацию:

  • Сохраните изменения.
  • Обновите конфигурацию базы данных.
  • Запустите режим «1С:Предприятие».
  • Откройте документ «Поступление товаров».

До выполнения команды Поле «Результат проверки» не должно отображаться на форме. Это подтверждает, что его исходное свойство Видимость имеет значение Ложь.

Шаг 7. Нажмите команду «Проверить данные»:

Обработчик:

  1. проверит значение «Объект.Склад»;
  2. сформирует текст в «РезультатПроверки»;
  3. выполнит «Элементы.РезультатПроверки.Видимость = Истина».

После этого поле «Результат проверки» должно появиться на форме.

В нем будет отображаться один из вариантов: «Необходимо указать склад» или «Данные заполнены корректно» в зависимости от текущего значения реквизита Склад.

Шаг 8. Проверьте обратное значение свойства:

Для понимания механизма можно временно заменить:

«Элементы.РезультатПроверки.Видимость = Истина» на «Элементы.РезультатПроверки.Видимость = Ложь».

В таком случае при выполнении команды элемент будет скрываться.

После эксперимента восстановите «Элементы.РезультатПроверки.Видимость = Истина».

Контрольный результат. Свойство «Видимость» позволяет программно изменять отображение элемента управляемой формы без удаления самого элемента и связанного с ним реквизита.
